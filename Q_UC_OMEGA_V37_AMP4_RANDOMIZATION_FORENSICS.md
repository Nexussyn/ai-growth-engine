## Finding 1: published study-level estimates are heterogeneous

Using only the three published aggregate estimates:

- AMP-TPP Study 1: p=0.4948, n=37,836
- AMP-TPP Study 2: p=0.4965, n=127,000
- AMP-TPP Study 3: p=0.5007, n=217,800

Inverse-variance fixed-effect heterogeneity calculations give:

- pooled fixed-effect p ≈ 0.49872
- Cochran Q ≈ 8.245
- df = 2
- Q-test p ≈ 0.0162
- I² ≈ 75.7%
- DerSimonian-Laird tau ≈ 0.00271 (absolute probability units)

These calculations are exploratory and use only three aggregate estimates. They do NOT establish a real physical or psychological effect, and the heterogeneity can arise from ordinary study-to-study variation, protocol differences, or hidden methodological structure.

## Finding 2: public AMP4 code contains a randomization implementation discrepancy worth investigating

The AMP4 public repository contains backend/src/random.js and backend/src/user.js.

random.js defines:

  const generate = () => new Alea()();
  const coinFlip = () => generate() >= 0.5;

and its Fisher-Yates shuffle uses Math.random():

  const j = Math.floor(Math.random() * (i + 1));

user.js uses coinFlip() for target-side generation and generate() for picture-number selection. It also uses random.shuffle() for picture lists.

The client-side script contains another shuffle implementation that uses server.random when available and otherwise Math.random(). The public backend adapter shown in the repository does not define server.random.

This is important because the published paper states that Alea was used for all randomization steps. The repository therefore warrants a version-locked code-to-paper audit to determine whether the exact deployed Study-3 code path matched the current public repository and whether every randomization operation was actually generated by Alea.

## What this does NOT show

It does not show:
- that target sequences were predictable to participants;
- that Study 2's anomaly was caused by the PRNG;
- that the published conclusions are invalid;
- that psi exists;
- that a causal anomaly exists.

The repository is historical software evidence. A causal claim requires reproducing the exact deployed commit, dependency versions, deployment configuration, and archived raw trial data.
